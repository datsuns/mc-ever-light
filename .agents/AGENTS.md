# Agent Rules - Minecraft Modding

本プロジェクトで稼働するAIエージェントが順守すべき追加ルールです。

## リソース消費の最適化（Quotaの節約）

1. **思考精度を損なわない範囲で、可能な限りAPIのQuota（トークン等）消費を抑えて動作すること。**
2. **情報の最小限化**: 
   - ファイルの読み込み（`view_file`）は、必要な行範囲を限定して行い、ファイル全体を無差別に読み込むことを避けます。
   - 変更履歴やコード差分を提示する際、変更のない大部分のコードを再出力せず、該当箇所のdiffや要点のみを出力します。
3. **対話と出力の簡潔さ**:
   - ユーザーへの返答やエージェント内の思考ログは、冗長な挨拶や過度な説明的文脈を省き、技術的に簡潔かつ明確に記述します。
   - すでに作成したドキュメント（アーティファクト等）の内容をチャット上で二重に要約・再掲することを避けます。
4. **ステップ数の最適化**:
   - 推論やツールの呼び出しにおいて、不要な繰り返し（ループ）や冗長な確認コマンドの実行を避け、最小限のステップで効率的にタスクを完了させます。

## Git操作のガイドライン

1. **適切な粒度でのコミット**: 意味のある機能単位、またはタスク単位で細かくコミットを行います。
2. **ADR（Architecture Decision Record）としてのコミットログ**: コミットメッセージには「何を変更したか」だけでなく、「なぜその設計・手法を選択したか」という判断の背景・理由（ADR）を明記します。

## ルール更新時の動作

1. **ルールのセルフレビュー**:
   - フィードバックループ等でルールファイルを更新・追加した際は、必ずルール全体を一度読み直してセルフレビューを行います。
   - 新旧のルール間で矛盾や重複が発生していないかを検証します。
2. **構成のブラッシュアップ**:
   - セルフレビューで矛盾、重複、または曖昧な表現を検出した場合は、ルールの整理・再配置を行い、より簡潔で一貫性のある構成へブラッシュアップします。

## 作業管理と進捗追跡のガイドライン

1. **条件付き計画・タスクリストの作成**:
   - ユーザーから「プラン検討」「設計」「計画作成」が明示的に指示された場合、または複数ステップを伴う大規模な機能開発・改修作業を行う場合に限り、事前に「作業プラン」と「タスク状況を示すファイル（TODOリスト）」を作成します。
   - 単発の質疑応答、軽微な確認・修正作業、単純な調査回答等ではファイルを作成せず、最小限のトークン消費で直接回答します。
2. **作業中のタスクリストの随時更新**:
   - プランおよびタスクリストを作成した作業の進行中は、タスク状況を示すファイルを適宜更新（完了マークの付与など）しながら作業を進めます。

## Mod開発におけるバージョン対応のガイドライン

1. **テンプレートプロジェクトの参照**:
   - 特定のバージョンへの対応を開始する際は、対象バージョンのテンプレートプロジェクトの内容を参考にします。
2. **公式テンプレートのダウンロード先**:
   - **Fabric**: https://fabricmc.net/develop/template/
   - **NeoForge**: https://neoforged.net/mod-generator/
